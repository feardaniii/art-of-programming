# 277 Techniques for Delivering Information

Concise English reference based on `ocr_text_paginated_cleaned_en.md`.

## What This Document Is

This PDF is a catalog of instructional-design techniques for building educational products: lessons, courses, workshops, calls, assignments, group activities, and visual explanations.

Each page describes one technique: what it is, when to use it, and often an example.

## Main Use

Use this as a checklist when designing a course or lesson:

- Structure the learning path.
- Explain concepts clearly.
- Add examples, visuals, tasks, and practice.
- Keep learners engaged emotionally and socially.
- Improve the product through feedback and iteration.

## Core Technique Families

### 1. Course And Lesson Architecture

Techniques for shaping the structure of a lesson or course before producing content.

Key techniques:

- Architecture: outline the lesson as a thesis-level structure.
- Theme / Rheme: introduce context first, then details.
- Through-line example: explain everything through one continuous example.
- Bifurcation point: show the key decision or event that changes the result.
- Kolb cycle: move from experience to reflection, theory, and practice.
- Occam's razor: remove unnecessary content.
- Learner mode: prepare students to participate and learn actively.
- Attention fangs: place emotional peaks around important content.
- Product packaging: define how the educational product is presented.
- Aspect model: split a topic into aspects.
- Step-by-step model: split a topic into sequential actions.
- Case-study model: teach through a real case.
- Experience-flow architecture: begin with lived experience, then extract theory.
- Universal model: actualize the topic, define concepts, show examples, explain actions, errors, nuances, and tasks.

### 2. Course Skeleton

Techniques for the visible building blocks of a course, module, lesson, or content unit.

Key techniques:

- Actualization: explain why the topic matters.
- Exercises / drills: practice the material.
- Takeaway summary: compress key points.
- Types / kinds: classify the subject.
- Announcement: preview what comes next.
- Meta-structure: show the course map or module map.
- Definition: explain the essence of a term.
- Life hacks: give non-obvious shortcuts.
- Strong promise: state the expected learner result.
- Case study: prove a result through a real story.
- Scheme: show relationships between parts.
- Example / anti-example: compare correct and incorrect execution.
- Helicopter view: show the whole system from above.
- Artifacts: use screenshots, photos, audio, video, documents, or statements as proof.
- Hero / character: introduce a learner-like character.
- Setting: create a visual and emotional world for the product.
- Rubrics: recurring labeled sections for navigation.
- Big rocks: modules, chapters, or lessons.
- Details and nuances: explain subtle pitfalls.
- Self-presentation: establish the speaker's credibility.
- Errors: teach through common mistakes.
- Algorithm: show "if this, then that" logic.
- Introduction: immerse the learner in the topic.
- Title page: identify the product with name, promise, and result.
- Case: package a learner result as social proof.

### 3. Real Changes

Techniques for making learning produce observable action.

Key techniques:

- Event / real change: design a concrete event that moves the learner toward the promise.
- Planned change template: give learners a worksheet for planning actions or changes.

### 4. Student Tasks

Task formats used to convert information into practice.

Key techniques:

- Speaking task: explain, discuss, or reflect aloud.
- Interactive tests: check understanding through interaction.
- Role play with script: practice behavior through a scenario.
- Text task: write, rewrite, analyze, or complete text.
- Calculation task: work with numbers.
- Real-world action: do something outside the lesson.
- Intellectual experiment: test an idea mentally or through a case.
- Brainstorming: generate options.
- Graphic task: draw, chart, map, or visualize.
- Situational modeling: simulate a management or production situation.
- Feedback / review task: analyze work and give critique.
- Templates: provide reusable forms.
- Checklists: reduce execution errors.
- Constructors: assemble outputs from parts.
- Blank cells: fill missing information.
- Money-result task: connect actions to financial outcome.
- Metric task: work with measurable indicators.
- Attempt-count task: require repeated tries.
- Practice-hour task: require time spent practicing.
- Expertise-search task: find and evaluate external expertise.

### 8. Product Improvement

Key techniques:

- Debriefing and reflection: convert observations into tasks.
- Built-in NPS collection: ask learners for a recommendation score.

## Page 45: Title Page

Page 45 defines the title page of an educational product.

A title page should contain:

- Product or unit name.
- Strong promise.
- Expected result after completion.

The PDF example is a unit called "Decomposition." Its promise is that the learner will calculate a business financial goal by dividends, profit, and revenue in pessimistic, realistic, and optimistic scenarios. The expected result is a decomposition table and a task list for reaching the desired business result.

## Bottom Line

This is not a general dictionary. It is a practical technique library for designing educational content. The main value is using the entries as a production checklist: choose the techniques that make a lesson clearer, more believable, more visual, more interactive, and easier to improve.
